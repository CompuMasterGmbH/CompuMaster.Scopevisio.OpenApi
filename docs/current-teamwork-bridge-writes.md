# Current Teamwork bridge mutations

`TeamworkApi.RemoveTeamworkResource`, `PutTeamworkResource` and `PostTeamworkResource` each provide synchronous data/HTTP-info and asynchronous data/HTTP-info forms, including native cancellation overloads. DELETE and PUT accept one to four segments; POST accepts one to three. All eleven current bridge mutation routes are covered. Existing handlers and `GetTeamworkResource` remain unchanged.

`TeamworkBridgeWriteRequest` copies original nonblank nondot segments, ordered query pairs (repeated keys and empty values included), and optional raw entity bytes. Collections are read-only and each `Body` getter returns a fresh copy. Each original segment is escaped exactly once, including percent-encoded-looking text; embedded slashes never add path segments. Query keys must be nonblank and values nonnull. No resource/version/tenant/endpoint names are rewritten or inferred.

A null body requires a null content type and omits the entity. An explicit empty byte array is different from absence and requires a valid explicit media type. The original media type is stored without normalization and must contain no line breaks; transport/header formatting can apply. JSON, URL-encoded forms and multipart payloads are caller-produced opaque bytes; the caller also supplies any multipart boundary. No serialization, Base64 conversion, file access, multipart construction, MIME or filename inference is performed. A DELETE payload is an explicit caller choice whose target support remains unverified.

OpenScope declares **no requestBody** for these routes and a default `*/*` object response, without a fixed success shape. Its [general documentation](https://help.scopevisio.com/en/articles/467359-general-documentation) delegates resource endpoints and permissions to CenterDevice and illustrates query forwarding under Scope OAuth. The manufacturer CenterDevice REST API v2.29 document includes JSON and multipart resource contracts. These additions expose optional opaque payload/query transport for explicit delegated contracts; isolated tests prove client wire behavior, not actual bridge acceptance or branded endpoint/version adaptation. They do not turn the absent OpenScope body schema into a declared target schema.

Responses preserve full buffered entity bytes, original status and combined response/content headers. `RawJsonContent` is null; no JSON, filename, location URI, success ID or access inference is made. Transport content decoding can apply; bytes are entity data rather than literal network packets. Empty entities produce empty arrays; null is retained if the transport supplies no bytes. The original exception factory runs before wrapping, including custom factories or an explicitly null factory. The default factory preserves HTTP errors and diagnostics, including 401; no retry is introduced.

The existing Scope OAuth context is used without account selection, additional reads, token installation or configuration changes. This low-level request cannot establish Scope organisation, user or Teamwork tenant identity. It does not resolve the observed bridge401 or establish direct OAuth registration/permissions. Mutation semantics and resource visibility remain target-authoritative; changes can affect files, collections, memberships or other resources according to the caller-selected endpoint. Cancellation can leave a mutation already applied and must not trigger blind replay.

Actual verification remains open and requires a new finite exclusive cross-repository window, exact numeric Demo Scope organisation and fresh account proof, separate opaque Teamwork tenant binding, explicitly owned reversible fixtures and complete verified cleanup. No PROD default fallback or historical grant reuse is permitted. Source/isolated validation is separate from SDK publication and DMS adoption.
