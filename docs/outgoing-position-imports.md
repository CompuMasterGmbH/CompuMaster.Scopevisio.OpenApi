# Explicit outgoing-invoice position XML imports

OutgoingInvoiceApi adds DeleteOutgoingInvoicePositions, UpdateAllOutgoingInvoicePositions and UpdateOutgoingInvoicePositions for the three /outgoinginvoices/deletepositions, /updateallpositions and /updatepositions POST routes. Each has six sync/async/HTTP-info/native-cancellation forms. Existing generated OutgoingInvoiceImportForm and methods remain unchanged.

OutgoingInvoicePositionImportRequest covers all ten current schema fields. Bodies are optional: null omits the body. A supplied body requires original data XML as a JSON string, including an explicit empty string because no minimum length is declared. The SDK does not parse, reformat, reconstruct or load XML from files. Original template strings, optional explicit JSON null, empty text, unknown fields and explicit false/true options are retained. generateDocumentNumbers, doPost, skipDuplicates, createPdf, copyProductToPosition, copyProductToPositionOverwriteMode, copyImpersonalAccountFieldsToPosition and copyVatKeyAndTaxRateToPosition are caller choices; the SDK inserts no default or automatic posting/PDF/number-generation action.

The manufacturer gives all three routes the same copied position-update summary and HTTP 200 description. It provides no fixed success schema or sufficiently detailed XML/selection/delete/update-all semantics. The separate method names expose the distinct routes without guessing an XML grammar, deriving affected invoices/positions, clearing an entire invoice in the client, inferring counts or reconciling current state. Exact operation/option interaction remains a live acceptance requirement. Angebote, Aufträge, Lieferscheine, Rechnungen (Bearbeiten), invoice state, usable XML and actual privileges remain server-enforced.

Source JSON is deeply copied and the complete transport body snapshots before HTTP I/O. Typed null setters omit properties; raw indexers preserve unknown fields and optional explicit JSON null. Known option kinds and the required data string are validated before transport.

Complete JSON results, exact raw content, HTTP status and response/content headers are retained. HTTP 200 can contain errors; callers must inspect the complete actual feedback instead of assuming every invoice/position succeeded. Unknown future result shapes remain accessible and empty bodies have null data. The configured exception factory runs before JSON parsing. Date-like strings remain strings; fractions use bounded .NET decimal precision and can round or underflow, while raw JSON remains exact.

No mutation retry or partial-failure replay is added. Native cancellation reaches HTTP I/O; cancellation after sending cannot establish which changes occurred. Nine missing-workflow tests fail before the API addition. Isolated fake HTTP tests cover every form, original XML/options, optional bodies/required string/known kinds, snapshots, complete feedback/errors/headers and active/pre-cancellation. No actual invoice positions are changed or removed and no invoice is posted. Exclusive coordinated live fixtures with owned invoice XML and verified restoration/cleanup remain pending. Full support, publication and downstream adoption remain separate.
