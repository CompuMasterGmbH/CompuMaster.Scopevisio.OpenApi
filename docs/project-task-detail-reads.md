# Complete project and task details

Issue #106 extends parent #17 and consuming CompuMasterGmbH/CompuMaster.Dms#90. GetProjectDetails and GetTaskDetails expose complete JToken results alongside historical generated GetProject/GetTask methods that retain their existing void/Object/null-data behavior. Each additive workflow has synchronous, HTTP-info, asynchronous and native cancellable asynchronous forms.

GET /project/{id} accepts optional fields and nullable formatValues. Null omits each query value; explicit empty fields and explicit false/true formatting choices are retained. The server documents formatting default true. GET /task/{id} accepts optional fields only; no formatting, search or paging parameters are fabricated. Both routes use original complete signed Int64 identifiers rendered with invariant culture; the current contract imposes no numeric minimum.

The manufacturer specifies no fixed success schemas for these routes. Complete JSON values preserve unknown fields, nested data, nulls and future envelope/array/object shapes. HTTP-info additionally retains the exact raw body, status and combined response/content headers. Date-like strings stay strings. Fractional values use .NET decimal precision and may round or exceed its range; the raw response remains exact.

The required profiles are Projekte (Anzeigen) and Aufgabe (Anzeigen). The current response tables list success without an exhaustive error catalogue. The configured exception factory receives the original response before additive JSON parsing and its exception instance is preserved; errors are not translated into inferred absence or permission decisions. Native cancellation reaches active CallApiAsync I/O. No token/account changes, retries, local formatting, relationship lookup or assumed model conversions are added.
