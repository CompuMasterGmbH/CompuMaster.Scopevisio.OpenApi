# VAT matrix replacement and selected-entry updates

`AccountingApi.ReplaceVatMatrixEntries` uses POST /vatmatrixentries and replaces the entire current organisation matrix. `UpdateVatMatrixEntries` uses PATCH /vatmatrixentries, updates entries by their IDs and maintains existing entries according to the manufacturer. Each has six sync/async/HTTP-info/native cancellation forms. These are distinct explicit choices; the client never decides between them, fetches/merges the current matrix or builds a JSON Patch document.

The request is an optional JArray: null omits the body, an empty array is sent exactly and a supplied object array snapshots deeply before HTTP I/O. A POST empty array may remove the existing matrix; it is never inferred from null or an omitted selection. The schemas declare no required entry fields/minimum records. Entry object shapes, Int64 id, finite numeric vatRate and the nine known text fields are checked without coercion, rate/range rules, guessed IDs or account interpretation. Unknown fields and explicit optional JSON null remain intact.

`VatMatrixEntryRequest` provides copied extensible JSON plus typed id/vatRate/datevKey/datevKeyReduced/vatKey/vatKeyDescription/vatCode/purchaseAccount/salesAccount/salesNotDueAccount/cashDiscountAccount properties. Typed null setters omit fields; the inherited indexer can retain explicit JSON null. Original account strings retain leading zeros, empty values and future catalog choices. Negative or high rates/IDs remain server validation choices; no client rate rounding is applied. Typed decimals are bounded by .NET precision; complete raw numeric tokens remain available.

The pinned contract lists Stammdaten, Steuermatrix (Anzeigen) for writes. The SDK preserves that documented profile statement without guessing a write-profile correction; actual authorization, tax configuration, account validity, PATCH matching and replacement semantics require server verification. The manufacturer declares HTTP 200 and unspecified response JSON, with HTTP 400 for missing mandatory server parameters. Complete JToken/status/raw JSON/response+content headers and original diagnostics are retained. A fixed list/count/result schema is not fabricated. Date-like result strings remain strings; parsed fractions use bounded .NET decimal precision and may round or underflow, while raw JSON remains exact.

No new mutation retry, client-side chart repair, follow-up or automatic compensation is added. Existing serializers/authentication/obsolete annotations/reads remain unchanged. Native cancellation reaches active HTTP I/O; cancellation after sending cannot establish whether the matrix was changed.

Isolated fake fixtures reproduce absent APIs and exercise POST versus PATCH, all public forms, full original fields, optional versus explicit empty/null choices, defensive copies, exact IDs/account strings/rates, malformed known kinds, undeclared results/errors/headers and pre/active cancellation. No actual tax matrix is accessed. Live testing requires an exclusive coordinated window, an explicitly owned organisation scope and verified complete restoration. Operation support remains deferred; this implementation does not authorize package publication or downstream default adoption.
