# CI platform coverage

Windows with .NET 8 retains the complete isolated SDK suite. The existing complete historical account suite remains a separate, credentialed path in the normal and scheduled account workflows. That legacy path is not the Demo-only acceptance harness and must not be dispatched for the new acceptance scope without coordinated account admission and a separately reviewed safe selection.

The entire secondary matrix executes 20 named, nonparameterized isolated unit cases in total: Windows/.NET Framework 4.8 gets eight, Linux/.NET 8 gets six, and macOS/.NET 8 gets six. `get-ci-test-selection.ps1` partitions the same 20 cases without overlap. The budget is shared across secondary platforms, frameworks and projects. Secondary targets do not execute the historical credentialed project, including when a caller passes `IncludeCredentialedSuite`. All existing SDK compilation targets remain built. The offline Ubuntu contract workflow validates the policy without repeating SDK runtime cases.

The sample covers token installation and refresh, explicit-organisation guards, bootstrap failures, active cancellation, escaped identifiers, invariant queries, numeric fidelity, binary report/export bytes, defensive copies, material response interpretation, invoice/DATEV inputs, posting/product cancellation without replay, and account/token metadata. These tests use fake transports and in-memory inputs. They do not read account credentials, profiles or workstation caches and do not contact real servers. Sample method names referring to imports or mutations describe fake HTTP tests.

Before any sample test executes, the runner builds the selected project and discovers its filtered cases from that build. Discovery must match every named nonparameterized method exactly once and stay within its eight- or six-case allocation. Missing, expanded, duplicated or unexpected entries fail before execution. Unknown VSTest listing formats fail closed. The same build runs with `--no-build`; TRX admission requires exactly the named passed cases, no skips or duplicates, consistent counters and counts within that target allocation. Discovery and TRX files are retained together. A final credential-free job requires all three secondary artifacts, revalidates their cases, rejects extra TRX reports and verifies the sum is exactly 20 actual executions. Missing or failed targets cannot become a complete matrix pass. A successful sample does not establish complete coverage on a secondary target.

Run credential-free policy regressions with `pwsh -File .github/scripts/test-ci-test-selection.ps1`. For a local sample, invoke `run-ci-tests.ps1` without `IncludeCredentialedSuite`, selecting Windows/net48 and a fresh results directory. Select Windows/net8 without that switch for the complete isolated suite. The credentialed Windows/net8 option is CI-only and requires maintained coordinated exclusive account access.

The normal and scheduled account workflows retain `openscope_test_account`, `cancel-in-progress: false` and `max-parallel: 1`. This repository-scoped lock does not exclude other repositories or local sessions. No source change enables a held workflow or grants account access. Preserve original workflow states, including the disabled scheduled workflow.

Manual dispatch of the normal workflow can set `include_credentialed_suite=false` for credential-free release validation: full isolated Windows/net8 coverage and the same combined 20-case secondary sample. The default remains true, preserving existing push, pull-request and manual account-test behavior. A false selection does not include the historical account project and does not require a new account window. For example: `gh workflow run BuildAndTest.yml --ref master -f include_credentialed_suite=false`.
