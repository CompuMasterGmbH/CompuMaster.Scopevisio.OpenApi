# Explicit recurring-invoice conversion scheduling

Parent [#17](https://github.com/CompuMasterGmbH/CompuMaster.Scopevisio.OpenApi/issues/17), focused [#164](https://github.com/CompuMasterGmbH/CompuMaster.Scopevisio.OpenApi/issues/164), consumer [DMS #90](https://github.com/CompuMasterGmbH/CompuMaster.Dms/issues/90).

OfferApi, OrderApi, OpportunityApi and OutgoingInvoiceApi add six ...ToRecurringInvoiceWithResult forms each, retaining existing ConvertInvoice terminology. Exact POST routes are the source path /offer|order|opportunity|outgoinginvoice/{number}/convertToRecurringInvoice. Required numbers remain original internal-number strings escaped as one segment; null/blank/exact-dot selectors fail before HTTP. No document-number mapping, target-account choice, hierarchy or resulting ID is inferred.

The body is optional. Null omits it without inserting scheduling. A supplied RecurringInvoiceConversionRequest requires validFrom, validTo and nextInvoiceDate as original signed Int64 Unix epoch milliseconds and frequency as one declared string. The copied extensible model starts with no defaults and reuses ConvertToRecurringInvoiceForm.FrequencyEnum: daily, weekly, monthly, bimonthly, quarterly, half-yearly and yearly. Typed null setters omit fields. Original zero/full-width/independently ordered epoch values remain unconverted. No monthly default, current date, year/month boundary, ordering, range minimum or client clock is used.

Shared internal RecurringConversionBody deeply copies, validates and serializes before HTTP admission. It checks required integer kinds/widths, exact declared frequency strings and finite JSON numbers. An empty object is distinct from body omission and fails because required properties are absent. Unknown fields remain intact. Undefined historical enum zero is rejected on this new path without changing old model serialization/defaults.

Profiles remain source-specific: Angebote (Bearbeiten), Aufträge (Bearbeiten), Rechnungen, Potenzial (Opportunities) (Bearbeiten), and Rechnungen (Bearbeiten), respectively. HTTP200 declares no success schema; full JToken/raw/status/response plus content headers remain available, including unknown/scalar/array/null results and original date strings. Empty response data is null. Parsed decimal fractions have bounded .NET precision; raw JSON remains exact. Original factories run before parsing. Documented404 can mean missing source or write permission.

Native cancellation prevents pre-canceled I/O and reaches active transport. Cancellation after sending does not establish conversion outcome; no retry or automatic follow-up is added. Historical ConvertToRecurringInvoiceForm constructors, zero timestamp/frequency defaults, generated methods and common account/token/transport behavior remain unchanged.

Initial 641 missing-model/form failures reproduced while four legacy regressions pass. Final 661 cases cover all 24 forms, omitted versus supplied bodies, all seven frequencies, complete copied/future/snapshot/invariant epoch choices, invalid required kinds/widths/frequencies, arbitrary results/raw/headers/factories/errors and pre/active cancellation. These handlers access only fake hosts. No financial document is converted on a real account. Actual conversion/scheduling/profile/number behavior, independent review/merge, complete server matrix, publication and DMS adoption remain separate.
