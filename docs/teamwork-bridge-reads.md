# Complete Teamwork bridge reads

The additive `TeamworkApi.GetTeamworkResource` provides synchronous, asynchronous and native-cancellation forms, each with an optional HTTP-info form. `TeamworkBridgeReadRequest` copies one to three original path segments and ordered query pairs. The current workflow escapes each original segment independently before transport, including encoded-looking text: literal `a%2Fb` is sent as `a%252Fb`, without decoding or adding a path segment. Repeated query keys, original values and empty values are preserved; keys must be nonblank because the existing transport rejects blank parameter names. Null query omits it. Null selections, unusable segment counts, blank/dot segments and null values fail before HTTP admission.

The three pinned GET routes declare only path placeholders and an unspecified default `*/*` response. [Manufacturer general documentation](https://help.scopevisio.com/de/articles/467359-general-documentation) additionally describes forwarding CenterDevice resources and their query parameters through the Scopevisio bridge, using Scopevisio OAuth and CenterDevice permissions. Query pairs are therefore explicit advanced resource choices; this method does not invent endpoint-specific models, permissions, paging, account choices or parameter defaults.

Responses retain complete buffered entity bytes, status and combined response/content headers. Accept is `*/*`; RawJsonContent is null. Arbitrary JSON, long fractions, date strings, HTML and binary files are not interpreted. Existing transport content decoding and buffering still apply; this is not a claim of literal network-packet identity. Callers own interpretation and later storage. The configured original exception factory runs before response wrapping. No child navigation, token installation, file writes or new retry is introduced.

The initial seventy-two isolated cases cover all three routes and six forms, independent segment escaping, copied read-only selection, ordered/repeated queries, empty values and entities, all256 byte values, opaque long-fraction/date JSON, headers/status, original errors/factory behavior, pre/active native cancellation, and historical bridge deserialization/token behavior. Initial tests reproduced 69 failures before the additive API existed; legacy behavior already passed. These fake-host tests do not establish actual bridge query, resource or permission acceptance. Live validation requires a new coordinated exclusive server window; publication and downstream DMS adoption remain separate parent #17/#90 prerequisites.

A focused literal-segment regression adds54 cases across one-to-three segments and all six current forms. Eighteen cases reproduce the changed a%2Fb spelling, while36 percent/dot-looking cases are controls; all126 current bridge-read cases pass after correction. Generated historical GetHandler APIs, the immutable read request, shared transport, buffering and response factory remain unchanged. The offline inventory recognizes the fixed literal read-path helper without accepting arbitrary dynamic paths; the parser manifest is repinned using two fresh byte-equal outputs with existing generated source unchanged. Real resource/tenant/permission acceptance remains open.
