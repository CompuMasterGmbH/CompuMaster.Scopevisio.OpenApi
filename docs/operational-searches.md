# Complete incoming-invoice, human-resource and event searches

Additive IncomingInvoiceApi.SearchIncomingInvoices, HumanResourcesApi.SearchHumanResources and ActivitiesApi.SearchEvents each provide six sync/HTTP-info/async/native-cancellation forms for POST /incominginvoices, /humanresources and /events. These routes search records; they do not create or change invoices, personnel or events.

The required server view profiles are Rechnungseingangsbuch for incoming invoices/events and Human-Ressourcen Verwaltung for human resources. The pinned bodies use optional JSON search filters; invoice/HR prose links the [manufacturer search-object documentation](https://help.scopevisio.com/de/articles/467360-search-scope-documentation). The existing extensible SearchRequest preserves original fields, criteria/operator/value types, explicit nulls, count/paging/format/order and unknown filters. Null omits the body; an empty request sends {}. Serialization completes before HTTP admission, with no default insertion, clamping, criteria rewriting, date/identifier/account lookup or automatic follow-up pages.

HumanResourcesResponse declares a records array referencing HumanResourcesType; complete JSON retains those records and future fields without inferred resource identities or allocations. Invoice/event success schemas are unspecified. Complete JToken, raw JSON, status and combined response/content headers preserve unknown objects, arrays, count scalars and explicit JSON null tokens. Empty responses have null Data. Date text remains strings; parsed fractions use bounded .NET decimal precision/range and may round, while raw JSON remains exact.

Original factory/errors remain authoritative before parsing; native cancellation reaches active HTTP I/O. No permission or account/capability decision and no new retry is introduced. Historical generated methods/body defaults remain unchanged: HR keeps its previous JObject deserialization; invoice/event methods keep null Data; all three keep their original quoted string-body behavior. Deprecated availability's required range body is separate and is not silently converted or redirected by these searches.

177 isolated fake-host cases cover all routes/forms, optional/empty/full original queries, invariant full-width numbers/decimal values, pre-admission serialization, complete future/date/raw/metadata, count/null/empty responses, invalid/overflow JSON, original factories/errors, pre/active cancellation and three preserved legacy paths. Before implementation 174 missing workflows failed while all three legacy regressions passed. Actual records/fields/profile/count/search behavior requires coordinated account/server acceptance. Complete required matrix, publication and downstream adoption remain separate parent #17/DMS #90 prerequisites.
