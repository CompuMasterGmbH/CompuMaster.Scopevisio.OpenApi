# Complete cashbook and sheet searches

Additive `CashbookApi.SearchCashbooks` and `SearchCashbookSheets` expose complete JSON results from POST `/cashbooks` and `/cashbooksheets` through six synchronous/HTTP-info/asynchronous/native-cancellation forms each. These POST endpoints search settings and sheets; they do not create entries or post money. Existing `GetCashbooks`/`GetCashbookSheets` methods and their string-body serialization/null-data defaults remain unchanged.

The pinned contracts accept optional JSON search filters and declare no success schemas. Their linked [manufacturer search documentation](https://help.scopevisio.com/de/articles/467360-search-scope-documentation) defines search objects, paging, fields, formatting, order and count. The existing extensible `SearchRequest` preserves original criteria, unknown filters, explicit JSON nulls and values. A null query omits the body; an empty query sends `{}`. Serialization completes before HTTP admission. Missing choices remain absent; negative/large paging values are forwarded for server validation without clamping, default insertion or automatic page requests. Count requests retain all original fields even though the server can ignore paging/field/order choices.

Settings require Kassenbücher Dashboard (Anzeigen). Sheets require Abgeschlossene Kassenblätter and Kassenbewegung eingeben (Anzeigen). The copied sheet response description says tasks, while its route/summary describe sheets; no task result model is inferred. Actual fields, results, count and profile behavior remain server-authoritative.

Complete JToken results preserve unknown objects, arrays, count scalars and explicit JSON null tokens; an empty response has null Data. Date strings remain strings; parsed fractions use .NET decimal precision/range and can round, while RawJsonContent preserves the original response. HTTP status, response/content headers, original exception factory and diagnostics remain intact. Native cancellation reaches active HTTP I/O. No account selection, cash entry mutation, retry or data normalization is added.

117 isolated fake-host cases cover all forms, omitted/empty/full original filters, full Int32/Int64 and decimal values under changed culture, pre-admission serialization, unknown/count/null/empty representations, raw/date/metadata, malformed/overflow JSON, original server/factory errors, pre/active cancellation and historical string-body/null-data/token behavior. 104 missing workflow failures were reproduced before implementation, with the legacy regression already passing. They establish no actual financial server behavior. Real acceptance needs a separately coordinated resettable test account and exclusive window; publication and downstream adoption remain parent #17/DMS #90 prerequisites.
