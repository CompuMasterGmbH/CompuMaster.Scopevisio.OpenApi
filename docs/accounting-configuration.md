# Explicit filter import and fiscal-year state edits

`AccountingApi.ImportFilters` and `EditFiscalYearState` add POST /filter/import and /fiscalyears/edit, each with six sync/async/HTTP-info/native cancellation forms. Existing generated APIs, authentication/defaults, serializer behavior and lookups remain unchanged.

`FilterImportRequest` copies complete JSON and exposes Data plus UpdateExistingFilters. The body is optional in the pinned contract: null omits it. When a body is supplied, data must be an original XML JSON string because the schema requires it; empty text remains explicit for server validation. The client does not read files, parse/validate XML, normalize whitespace/entities or re-encode it. updateExistingFilters is optional boolean: omission retains the documented server default false, while false/true and raw optional JSON null remain distinct. The server matches existing filters by name when updating is requested and enforces Datenimport (Bearbeiten).

`FiscalYearStateRequest` exposes original fiscalYearName, optional Int32 periodId and nullable Open. Omitted fields remain omitted, an empty object stays empty and true/false are caller-explicit choices. The schema requires no individual fields or period-ID range beyond Int32. The SDK validates known raw kinds/width without choosing the active year/period or inferring an opening/closing default. The server determines the selected year/period versus whole-year action, actual state, Journal (Bearbeiten) permissions and business constraints. HTTP 409 conflicts remain original; no state lookup, automatic year completion or repair occurs.

Both models preserve unknown fields and explicit optional JSON null through inherited indexers; typed null setters omit fields. Source objects and transport bodies are deep snapshots before HTTP I/O. Original names/IDs/booleans/XML remain unchanged.

The manufacturer declares HTTP 200 without fixed success schemas. Filter-import response/error descriptions incorrectly mention a posting and zone; this does not establish a posting operation or aggregate success. Complete JToken/raw JSON/status/response+content headers and original server diagnostics/custom factory exceptions are retained. Date-like result strings remain strings; parsed fractions use bounded .NET decimal precision and may round or underflow, while raw JSON remains exact. Empty responses have null data and future result shapes remain available.

No new mutation retry, partial-failure replay or follow-up is added. Native cancellation reaches active HTTP I/O; cancellation after sending cannot establish whether filters/year state were changed. Isolated fake tests reproduce missing public workflows and verify all forms, exact XML/name/period/open choices, optional/empty/null/default distinctions, raw kinds/widths, deep snapshots, complete results/error factories/headers and pre/active cancellation. No actual filters, banking rules or fiscal periods are changed. Live name-match/import/state/profile/business-constraint acceptance requires exclusive coordinated access and verified exact owned restoration/cleanup; full support remains deferred. Publication/downstream adoption are separate.
