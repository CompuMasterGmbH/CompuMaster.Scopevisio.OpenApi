# Complete accounting-report exports

ReportApi.DownloadAccountingReport and its HTTP-info/native asynchronous forms return complete buffered export bytes for GET /reports/{type}. ReportExportRequest captures all eight current choices: required type/startDate/endDate and optional reportName/outputFormat/includeHeader/includeZeroValued/splitDimensions. The historical generated GetReport omits splitDimensions and discards successful output; it remains unchanged.

The request is copied before HTTP admission. Original date strings retain the documented dd.MM.yyyy meaning without calendar/timezone conversion or local validity guesses. Optional null omits a query choice; explicit empty strings and false flags remain distinct. No outputFormat is inserted when omitted, preserving the server default of csv. The documented type catalog contains susa_account, susa_debitor, susa_creditor, bilanz, guv and bwa; formats contain pdf, csv, xml and json. Catalog availability, date validity and report-name applicability remain server-authoritative. Forwarding future or invalid strings in isolated tests does not establish backend support for them.

Report names apply to bilanz/guv/bwa. Original comma-separated splitDimensions indices and order are retained without parsing or dimension lookups. The Berichte, Debitoren, Kreditoren (Anzeigen) profiles are required. A documented 404 indicates an unknown selected report name; original diagnostics, HTTP500 and the caller's exception factory remain authoritative.

The bodyless GET requests Accept */*. All bytes, empty output, status and combined response/content headers are preserved. RawJsonContent is null even when JSON output was explicitly requested because this download does not parse output. The current transport buffers the complete response in memory; the caller owns any subsequent parsing or storage. No CSV/PDF/XML/JSON conversion, MIME/filename inference, report generation command, file writing or speculative replay is introduced. Native cancellation reaches admission and active HTTP I/O; existing configuration/token/account behavior remains intact.

[SDK #120](https://github.com/CompuMasterGmbH/CompuMaster.Scopevisio.OpenApi/issues/120) tracks fake .invalid query/snapshot/byte/error/cancellation fixtures, compiled compatibility and remaining coordinated real report/format/date/dimension/profile verification. Publication and downstream adoption remain separate.
